## پل فرمان (Command Bridge)

به عنوان لایه ارتباطی بین Atlas و Termux عمل می‌کند.

### مدل دوگانه ارتباطی (Dual-Connection Model)

Atlas از **دو مکانیزم جداگانه** برای دو نوع اجرای متفاوت استفاده می‌کند:

```
┌─────────────────────────────────────────────┐
│              رابط کاربری Atlas               │
└──────────────────┬──────────────────────────┘
                   │
       ┌───────────┴───────────┐
       ▼                       ▼
┌──────────────┐      ┌──────────────────┐
│  Quick Exec  │      │  Interactive     │
│  RunCommand  │      │  Terminal (PTY)  │
│  (Intent)    │      │  (Stream)        │
└──────┬───────┘      └────────┬─────────┘
       │                       │
       ▼                       ▼
┌──────────────────┐   ┌──────────────────┐
│  Termux          │   │  Termux          │
│ (One-shot Exec)  │   │  (PTY Session)   │
└──────────────────┘   └──────────────────┘
```

### مدل ۱: اجرای سریع (Quick Exec) — Termux:RunCommand

**مکانیزم:** Intent-based (One-shot)
**کاربرد:** فقط برای دستورات غیرتعاملی

**مناسب برای:**
- اجرای اسکریپت‌های سریع (python3 main.py)
- دستورات سیستمی ساده (ls, pwd, df)
- عملیات یک‌باره (git pull)
- اجرای پس‌زمینه (background jobs)

**محدودیت (مهم):**
- ❌ برای ترمینال تعاملی مناسب نیست
- ❌ برنامه‌های تعاملی (vim, htop, nano) با این روش **غیرممکن** است
- ❌ ورودی لحظه‌ای (stdin) پشتیبانی نمی‌شود
- ❌ خروجی لحظه‌ای (live output) پشتیبانی نمی‌شود

### مدل ۲: ترمینال تعاملی (Interactive Terminal) — PTY / Socket Stream

**مکانیزم:** Local Socket / PTY Stream
**کاربرد:** ترمینال اصلی Atlas (تب‌ها، Session‌ها)

**پشتیبانی از:**
- ✅ برنامه‌های تعاملی (vim, htop, nano, ssh)
- ✅ ورودی لحظه‌ای (stdin)
- ✅ خروجی لحظه‌ای (live output)
- ✅ ANSI Colors (رندر کامل)
- ✅ Multiple Tabs / Sessions پایدار

**نحوه عملکرد PTY:**
```
Atlas Terminal View
        ↓
Local Socket / PTY Stream
        ↓
Termux PtySession
        ↓
Linux Shell (interactive)
```

**اجرا تکنولوژی:**
- Terminal Emulator Library (libvterm / termux-app components)
- Local Socket (Unix Domain Socket)
- PTY Stream از طریق Termux API

### مدل ۳: Atlas Pro — Termux Session API (v2.0+)

**مکانیزم:** Plugin-based (پیشرفته)
**کاربرد:** ابزارهای توسعه

- ویرایشگر کد: Session API
- مرکز Git: Session API
- مدیر SSH: Session API
- ترمینال پیشرفته: Session API

**مزایا:**
- Session‌های متعدد و پایدار
- I/O لحظه‌ای کامل
- پشتیبانی از چند Shell همزمان
- دسترسی کامل به فایل‌ها (از طریق Service)

### خلاصه مدل‌ها

| مدل | کاربرد | تعاملی | Session | مناسب برای |
|-----|--------|--------|---------|------------|
| ۱. RunCommand | دستورات سریع | ❌ | ❌ | اسکریپت، دستورات سیستم |
| ۲. PTY/Socket | ترمینال اصلی | ✅ | ✅ | ترمینال، برنامه‌های تعاملی |
| ۳. Session API | ابزارهای Pro | ✅ هوشمندانه | ✅ | ویرایشگر، Git، SSH |
مسئولیت‌ها:

- دریافت اعمال کاربر
- ساخت درخواست‌های دستور
- ارسال دستورات به Termux
- دریافت خروجی دستور
- بازگرداندن خروجی به رابط کاربری

پل فرمان هیچ منطق تجاری ندارد.

تنها کار آن ارتباط است.

### رابط API

```kotlin
interface CommandBridge {
    suspend fun executeCommand(command: String): CommandResult
    suspend fun openSession(): Session
    suspend fun closeSession(sessionId: String)
    suspend fun listSessions(): List<Session>
    suspend fun readOutput(sessionId: String): Output
    suspend fun writeInput(sessionId: String, input: String)
    suspend fun getWorkingDirectory(sessionId: String): String
    suspend fun getEnvironmentVariables(sessionId: String): Map<String, String>
}

data class CommandResult(
    val output: String,
    val exitCode: Int,
    val error: String?
)

data class Session(
    val id: String,
    val workingDirectory: String,
    val environment: Map<String, String>
)

data class Output(
    val text: String,
    val colors: List<ColorSpan>,
    val cursorPosition: Int
)
```

# دسترسی به فایل‌ها (Scoped Storage)

## مشکل

Termux در UID مجزا از Atlas اجرا می‌شود.

مسیر Termux (`/data/data/com.termux/files/home`) **ایزوله** است.

اپ دوم (Atlas) مستقیماً به فایل‌های داخلی Termux **دسترسی ندارد**.

مگر در یکی از این شرایط:

## راهکارها

### راهکار ۱: Termux:API FileProvider (توصیه شده)

- استفاده از Termux:API برای دسترسی به فایل‌ها
- از طریق Content Provider اطلاعات فایل دریافت می‌شود
- نیاز به نصب Termux:API Plugin
- ✅ ساده و امن
- ✅ نیاز به امضای اپ ندارد

### راهکار ۲: Daemon / Local Bridge

- یک Daemon سبک در Termux اجرا می‌شود
- از طریق Unix Domain Socket ارتباط برقرار می‌شود
- Daemon فایل‌ها را می‌خواند و به Atlas برمی‌گرداند
- ✅ انعطاف‌پذیر
- ⚠️ پیچیده‌تر

### راهکار ۳: Shared UID / Signature (پیشرفته)

- Atlas با همان امضای Termux منتشر شود
- UID مشترک → دسترسی مستقیم به فایل‌ها
- ✅ کارآمد
- ❌ نیاز به امضای یکسان Termux دارد

## تصمیم نهایی برای v1.0

**راهکار ۱ (Termux:API FileProvider)** به عنوان راهکار اولیه انتخاب شد.

دسترسی کامل به فایل‌ها فقط در Pro (v2.0+ از طریق Daemon) ممکن است.

# مدل Session ترمینال

## چرخه حیات Session

```
ایجاد شده → در حال اجرا → متوقف شده → نابود شده
```

## وضعیت Session

- **فعال:** در حال اجرا (نشانگر سبز)
- **غیرفعال:** در پس‌زمینه (نشانگر خاکستری)
- **بسته شده:** بسته شده (حذف از رابط کاربری)

## ماندگاری Session

- ذخیره در SharedPreferences
- بازیابی در صورت Crash
- حداکثر ۱۰ Session

## مدیریت Session

- کشیدن برای بستن
- فشردن طولانی برای تغییر نام
- ضربه برای تغییر

# مدیریت خطا

اگر Termux خطا برگرداند:

Atlas Lite نمایش می‌دهد:

- عنوان خطا
- پیام خطا
- پیشنهادات اختیاری

Atlas Lite هرگز خطاهای Termux را مخفی نمی‌کند.

## انواع خطا

- **TermuxNotInstalled:** Termux نصب نشده است
- **PermissionDenied:** مجوز رد شد
- **CommandNotFound:** دستور پیدا نشد
- **SessionClosed:** Session بسته شد
- **ExecutionTimeout:** تایم‌اوت اجرا
- **UnexpectedFailure:** خطای غیرمنتظره

## نمایش خطا

- عنوان: نوع خطا
- پیام: توضیح خطا
- پیشنهادات: پیشنهادات رفع خطا
- عمل: دکمه تلاش مجدد
