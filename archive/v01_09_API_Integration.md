# مشخصات یکپارچه‌سازی Termux
> نسخه: ۱.۰ | تاریخ: ۲۰۲۶/۰۸/۰۶

---

# هدف

این سند توضیح می‌دهد Atlas Lite چگونه با Termux ارتباط برقرار می‌کند.

Atlas Lite هرگز مستقیماً دستورات Linux را اجرا نمی‌کند.

تمام اجرای دستورات به Termux واگذار می‌شود.

---

# اهداف طراحی

- ارتباط را ساده نگه دار
- از تغییر Termux اجتناب کن
- با نسخه‌های آینده Termux سازگار بمان
- تا جایی که ممکن است از مکانیسم‌های ارتباطی رسمی استفاده کن
- رابط کاربری را از اجرا جدا نگه دار

---

# مدل یکپارچه‌سازی

```
رابط کاربری Android
    ↓
کنترل‌کننده Atlas
    ↓
پل فرمان (Command Bridge)
    ↓
رابط Termux
    ↓
Termux
    ↓
Shell Linux
```

---

# مسئولیت‌ها

## رابط کاربری Atlas

مسئول:

- تعامل کاربر
- نمایش خروجی
- ناوبری
- تم‌ها
- رندر ترمینال

رابط کاربری هرگز مستقیماً با Linux ارتباط برقرار نمی‌کند.

## کنترل‌کننده Atlas

مسئول:

- پردازش اعمال دکمه
- دریافت رویدادهای رابط کاربری
- آماده‌سازی درخواست‌های دستور

## پل فرمان (Command Bridge)

مسئول:

- ارسال دستورات
- دریافت نتایج
- بازگرداندن خروجی به رابط کاربری

پل هیچ منطق Linux ندارد.

 ### مدل ۱: اجرای سریع (Quick Exec) — Termux:RunCommand

 **مکانیزم:** Intent-based (One-shot)
 **پلاگین مورد نیاز:** Termux:RunCommand (اختیاری)
 **کاربرد:** فقط دستورات غیرتعاملی

 **نحوه عملکرد:**
 1. Atlas دستور را دریافت می‌کند
 2. Intent با action `com.termux.RUN_COMMAND` ارسال می‌شود
 3. Extra ها تنظیم می‌شوند:
    - `com.termux.RUN_COMMAND_PATH`: مسیر دستور
    - `com.termux.RUN_COMMAND_ARGUMENTS`: آرگومان‌ها
    - `com.termux.RUN_COMMAND_WORKDIR`: مسیر کاری
    - `com.termux.RUN_COMMAND_BACKGROUND`: اجرای پس‌زمینه
 4. Termux دستور را اجرا می‌کند
 5. خروجی برگردانده می‌شود

 **مزایا:**
 - ساده و سبک
 - نیاز به Plugin اجباری ندارد
 - فقط Intent می‌خواهد
 - مناسب برای دستورات سریع

 **محدودیت‌ها (مهم):**
 - ❌ برای ترمینال تعاملی مناسب نیست
 - ❌ برنامه‌های تعاملی (vim, htop, nano) **غیرممکن** است
 - ❌ ورودی لحظه‌ای (stdin) پشتیبانی نمی‌شود
 - ❌ خروجی لحظه‌ای (live output) پشتیبانی نمی‌شود
 - ❌ Session پایدار ندارد

 ### مدل ۲: ترمینال تعاملی (Interactive Terminal) — PTY / Socket Stream

 **مکانیزم:** Local Socket / PTY Stream
 **پلاگین مورد نیاز:** Termux:API (اجباری برای ترمینال تعاملی)
 **کاربرد:** ترمینال اصلی Atlas (تب‌ها، Session‌ها)

 **نحوه عملکرد:**
 ```
 Atlas Terminal View
         ↓
 Local Socket / PTY Stream
         ↓
 Termux PtySession
         ↓
 Linux Shell (interactive)
 ```

 **پشتیبانی از:**
 - ✅ برنامه‌های تعاملی (vim, htop, nano, ssh)
 - ✅ ورودی لحظه‌ای (stdin)
 - ✅ خروجی لحظه‌ای (live output)
 - ✅ ANSI Colors (رندر کامل)
 - ✅ Multiple Tabs / Sessions پایدار
 - ✅ Cursor Style و Auto-complete

 **اجرا تکنولوژی:**
 - Terminal Emulator Library (libvterm / termux-app components)
 - Local Socket (Unix Domain Socket)
 - PTY Stream از طریق Termux API

 ### مدل ۳: Atlas Pro — Termux Session API (v2.0+)

 **مکانیزم:** Plugin-based (پیشرفته)
 **پلاگین مورد نیاز:** Termux:API (اجباری)
 **کاربرد:** ابزارهای توسعه

 **نحوه عملکرد:**
 1. Atlas Plugin به Termux متصل می‌شود
 2. Session ایجاد می‌شود
 3. I/O لحظه‌ای انجام می‌شود
 4. Session مدیریت می‌شود

 **ابزارهای مورد نیاز Pro:**
 - ویرایشگر کد: Session API
 - مرکز Git: Session API
 - مدیر SSH: Session API
 - ترمینال پیشرفته: Session API

 **مزایا:**
 - Session‌های متعدد و پایدار
 - I/O لحظه‌ای کامل
 - مناسب برای ابزارهای پیشرفته
 - پشتیبانی از چند Shell همزمان
 - دسترسی کامل به فایل‌ها (از طریق Service)

 **محدودیت‌ها:**
 - نیاز به Termux:API Plugin دارد
 - پیچیده‌تر از RunCommand
 - نیاز به مدیریت Session دارد

 ### خلاصه مدل‌ها

 | مدل | کاربرد | تعاملی | Session | Plugin مورد نیاز |
 |-----|--------|--------|---------|------------------|
 | ۱. RunCommand | دستورات سریع | ❌ | ❌ | اختیاری |
 | ۲. PTY/Socket | ترمینال اصلی | ✅ | ✅ | Termux:API (اجباری) |
 | ۳. Session API | ابزارهای Pro | ✅ | ✅ | Termux:API (اجباری) |

 # دسترسی به فایل‌ها (File Access)

 ## مشکل: Scoped Storage در Android 11+

 Termux در UID مجزا اجرا می‌شود.

 مسیر Termux (`/data/data/com.termux/files/home`) ایزوله است.

 اپ دوم (Atlas) مستقیماً به فایل‌های Termux دسترسی ندارد.

 ## راهکارها

 ### راهکار ۱: Termux:API FileProvider (توصیه شده)

 - از طریق Content Provider اطلاعات فایل دریافت می‌شود
 - مناسب برای: خواندن، پیش‌نمایش، کپی (از طریق Termux)
 - نیاز به نصب Termux:API

 ### راهکار ۲: Daemon / Local Bridge (پیشرفته)

 - Daemon سبک در Termux اجرا می‌شود
 - Unix Domain Socket برای ارتباط
 - مناسب برای: ویرایش، انتقال، عملیات پیچیده
 - در Pro (v2.0+) استفاده می‌شود

 ### راهکار ۳: Shared UID / Signature

 - Atlas با امضای یکسان Termux منتشر شود
 - UID مشترک → دسترسی مستقیم
 - فقط برای فورک Termux مناسب است

 ## تصمیم نهایی

 - **Lite v1.0:** راهکار ۱ (FileProvider) — خواندن و پیش‌نمایش
 - **Pro v2.0+:** راهکار ۲ (Daemon) — مدیریت کامل فایل
## رابط Termux

هدف: ارائه یک نقطه ارتباطی واحد با Termux.

هر ارتباط بین Atlas و Termux از این لایه عبور می‌کند.

اگر روش یکپارچه‌سازی در آینده تغییر کرد، فقط این لایه باید به‌روز شود.

# عملیات پشتیبانی شده

## اجرای دستور

- **ورودی:** command: String
- **خروجی:** CommandResult { output, exitCode, error }
- **خطا:** CommandNotFoundException, ExecutionTimeoutException

## باز کردن Session ترمینال

- **ورودی:** هیچ
- **خروجی:** Session { id, workingDirectory, environment }
- **خطا:** MaxSessionsReachedException

## بستن Session

- **ورودی:** sessionId: String
- **خروجی:** هیچ
- **خطا:** SessionNotFoundException

## لیست Session‌ها

- **ورودی:** هیچ
- **خروجی:** List<Session>
- **خطا:** هیچ

## خواندن خروجی

- **ورودی:** sessionId: String
- **خروجی:** Output { text, colors, cursorPosition }
- **خطا:** SessionNotFoundException

## نوشتن ورودی

- **ورودی:** sessionId: String, input: String
- **خروجی:** هیچ
- **خطا:** SessionNotFoundException

## دریافت مسیر جاری

- **ورودی:** sessionId: String
- **خروجی:** String
- **خطا:** SessionNotFoundException

## دریافت متغیرهای محیطی

- **ورودی:** sessionId: String
- **خروجی:** Map<String, String>
- **خطا:** SessionNotFoundException

# چرخه حیات دستور

```
کاربر دکمه را فشار می‌دهد
    ↓
رویداد رابط کاربری تولید می‌شود
    ↓
نوع رویداد: ExecuteCommand
    ↓
بار: { command: "ls -la" }
    ↓
کنترل‌کننده Atlas
    ↓
اعتبارسنجی ورودی
    ↓
دستور ساخته می‌شود
    ↓
پل فرمان
    ↓
دستور دریافت می‌شود
    ↓
ارسال به رابط Termux
    ↓
رابط Termux
    ↓
دستور به Termux ارسال می‌شود
    ↓
Session مدیریت می‌شود
    ↓
Termux
    ↓
دستور اجرا می‌شود
    ↓
خروجی تولید می‌شود
    ↓
جریان خروجی
    ↓
رابط Termux → پل فرمان → کنترل‌کننده Atlas → رابط کاربری → کاربر
    ↓
جریان خطا (در صورت خطا)
    ↓
خطا گرفته می‌شود → خطا نمایش داده می‌شود → کاربر مطلع می‌شود
```

# مدل Session ترمینال

## چرخه حیات Session

```
ایجاد شده → در حال اجرا → متوقف شده → نابود شده
```

## وضعیت Session

- **فعال:** در حال اجرا (نشانگر سبز)
- **غیرفعال:** در پس‌زمینه (نشانگر خاکستری)
- **بسته شده:** بسته شده (حذف از رابط کاربری)

## ماندگاری Session

- ذخیره در SharedPreferences
- بازیابی در صورت Crash
- حداکثر ۱۰ Session

## محدودیت‌های Session

- حداکثر ۱۰ Session همزمان
- حداقل ۱ Session (هرگز بسته نمی‌شود)

## مدیریت Session

- کشیدن برای بستن
- فشردن طولانی برای تغییر نام
- ضربه برای تغییر

# پردازش خروجی


هیچ خروجی نباید تغییر کند.

## رنگ‌های ANSI

- رنگ‌های پس‌زمینه

- اسکرول: روان

# مدیریت خطا

## خطاهای ممکن

- Termux نصب نشده
- مجوز رد شد
- دستور پیدا نشد
- Session بسته شد
- تایم‌اوت اجرا
- خطای غیرمنتظره

## نمایش خطا

- عنوان: نوع خطا
- پیام: توضیح خطا
- پیشنهادات: پیشنهادات رفع خطا
- عمل: دکمه تلاش مجدد

## انواع خطا

- **TermuxNotInstalled:** "Termux نصب نشده است. لطفاً Termux را از F-Droid نصب کنید."
- **PermissionDenied:** "مجوز رد شد. لطفاً مجوز حافظه را اعطا کنید."
- **CommandNotFound:** "دستور پیدا نشد: {command}. لطفاً ورودی خود را بررسی کنید."
- **SessionClosed:** "Session بسته شد. لطفاً Session جدیدی باز کنید."
- **ExecutionTimeout:** "تایم‌اوت اجرا. دستور زمان زیادی گرفت."
- **UnexpectedFailure:** "خطای غیرمنتظره. لطفاً دوباره تلاش کنید."

# مجوزهای Android

فقط مجوزهایی را درخواست کن که واقعاً مورد نیاز هستند.

## مجوزهای مورد نیاز

- **حافظه:** برای دسترسی به فایل (در صورت نیاز)
- **اعلان‌ها:** برای سرویس پیش‌زمینه
- **Termux API:** اختیاری، برای ویژگی‌های پیشرفته

## مجوزهای اختیاری

- **اینترنت:** برای ویژگی‌های ابری آینده
- **دوربین:** برای اسکن QR Code آینده
- **موقعیت مکانی:** برای ویژگی‌های مبتنی بر موقعیت آینده

از مجوزهای غیرضروری اجتناب کن.

# سازگاری

نسخه‌های Android هدف باید با نسخه‌های پشتیبانی شده Termux سازگار بمانند.

از جزئیات پیاده‌سازی که به وصله‌های غیررسمی وابسته‌اند اجتناب کن.

## نسخه‌های Android پشتیبانی شده

- Android 7.0 (API 24) حداقل
- Android 14 (API 34) هدف

## سازگاری Termux

- Termux 0.118.0+ توصیه شده
- تست با آخرین نسخه پایدار

# امنیت

Atlas هرگز نباید:

- دستورات پنهان را اجرا کند
- اسکریپت‌های کاربر را تغییر دهد
- پیکربندی Shell را بدون رضایت تغییر دهد
- تاریخچه دستورات را به صورت خارجی ارسال کند
- تحلیل‌ها را بدون رضایت کاربر جمع‌آوری کند

## ذخیره داده

- **رمزهای عبور:** ذخیره نمی‌شوند
- **کلیدهای SSH:** ذخیره نمی‌شوند (در v1.0)
- **توکن‌های API:** ذخیره نمی‌شوند (در v1.0)
- **کلیدهای خصوصی:** ذخیره نمی‌شوند

## مجوزها

- فقط در صورت نیاز درخواست کن
- توضیح بده چرا مورد نیاز است
- اجازه رد بدون Crash بده

## رمزگذاری

- SharedPreferences: رمزگذاری نشده (در v1.0)
- پایگاه داده: رمزگذاری نشده (در v1.0)
- آینده: یکپارچه‌سازی Android Keystore

# ثبت وقایع

فقط رویدادهای برنامه را ثبت کن.

هرگز ثبت نکن:

- رمزهای عبور
- کلیدهای خصوصی
- توکن‌های API
- ورودی حساس ترمینال

ثبت وقایع باید اختیاری و در پیش‌فرض غیرفعال باشد.

## انواع لاگ

- **رویدادهای برنامه:** شروع، پایان، خطاها
- **اعمال کاربر:** کلیک، تایپ، جستجو
- **رویدادهای سیستم:** Crash, ANR

## سطوح لاگ

- **Debug:** اطلاعات دقیق
- **Info:** اطلاعات کلی
- **Warning:** هشدارها
- **Error:** خطاها

## ذخیره لاگ

- **Logcat:** برای توسعه‌دهندگان
- **فایل:** اختیاری (برای عیب‌یابی)

## حریم خصوصی لاگ

- بدون رمز عبور
- بدون کلید
- بدون توکن
- بدون دستورات حساس
